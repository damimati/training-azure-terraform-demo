📋 Project Overview

This is a comprehensive Terraform training project that demonstrates how to build a production-ready Azure infrastructure. It showcases Infrastructure as Code (IaC) best practices, resource management, and network architecture design patterns for enterprise cloud deployments.

✨ Key Features

Multi-Network Architecture

Dual Virtual Network setup with separate address spaces, enabling advanced network segmentation and peering capabilities for complex deployments.

Layered Security

Network Security Groups (NSGs) for app, web, and database subnets with configurable ingress/egress rules and network isolation.

Subnet Segmentation

Organized subnet structure with app, web, and database tiers in both VNets, plus gateway and bastion subnets for secure access.

Network Peering

Bidirectional VNet peering with traffic forwarding and gateway transit configuration for seamless inter-network communication.

Advanced Routing

Custom route tables with specific routes for both generic and database traffic, supporting complex routing scenarios.

Virtual Machine Deployment

Multiple Windows Server 2022 instances with IIS installation via custom script extensions, using count meta-argument for scalability.

⚙️ Terraform Configuration Files

main.tf - Core Infrastructure

Contains the primary resource definitions:

  • Resource Group: Foundation for all Azure resources
  • Virtual Networks: Two separate VNets with distinct address spaces
  • Subnets: App, Web, DB, Bastion, and Gateway subnets
  • Network Security Groups: Firewall rules for each subnet tier
  • Route Tables: Custom routing policies
  • VNet Peering: Connection between VNets
  • Windows Virtual Machines: 3 instances deployed with count meta-argument
  • VM Extensions: IIS installation via CustomScriptExtension
Example: VNet Peering Configuration
resource "azurerm_virtual_network_peering" "mati_own_peering01to02" { name = "${local.generic_name}-peering-vnet01tovnet02" resource_group_name = azurerm_resource_group.mati_own_rg1.name virtual_network_name = azurerm_virtual_network.mati_own_vnet_name.name remote_virtual_network_id = azurerm_virtual_network.mati_own_vnet_name-02.id allow_virtual_network_access = true allow_forwarded_traffic = true }

variables.tf - Configuration Inputs

Defines all input variables for infrastructure customization:

  • subscription_id: Azure subscription identifier
  • resource_group_name: Target resource group
  • vnet_name & vnet_name-02: Virtual network names
  • address_space variables: CIDR blocks for networks and subnets
  • appsubnet, websubnet, dbsubnet: Subnet naming for each tier
  • admin_password: VM admin credentials
  • dns_servers: Custom DNS configuration
  • vm_to_create: Map variable for VM count iteration
  • ssh_pubkey_path: SSH key location for authentication
Example Variable Definition
variable "vnet_name" { description = "Name for virtual network" type = string } variable "address_space" { description = "Virtual Network defined address space" type = list(string) }

Loadbalancer.tf - Load Balancing (Optional)

Contains optional Azure Load Balancer resources:

  • Public IP: Static public IP for load balancer
  • Load Balancer: Standard SKU for high availability
  • Backend Pool: Target VMs for load balancing
  • Health Probe: TCP-based health checks on port 80
  • Load Balancer Rule: HTTP traffic routing (80→80)
  • NAT Rule: RDP access rule (3389) for remote desktop
  • NIC Association: Link VMs to backend pool

Note: Currently commented out. Uncomment to enable load balancing.

Other Configuration Files

providers.tf

Specifies the Terraform provider and required versions for Azure.

terraform.tfvars

Contains actual values for all variables defined in variables.tf. Customize this file with your Azure environment values.

outputs.tf

Exports important resource information after deployment (VNet IDs, subnet IDs, VM details, etc.)

backend.tf

Configures Terraform state storage (typically Azure Storage Account for remote state management).

local.tf

Defines local values for common naming conventions and tags applied to all resources.

🚀 Deployment Workflow

Step 1: Clone repository and configure Azure CLI authentication
Step 2: Update terraform.tfvars with your Azure subscription details
Step 3: Run terraform init to initialize Terraform working directory
Step 4: Execute terraform plan to review resource creation plan
Step 5: Run terraform apply to deploy resources to Azure
Step 6: Monitor deployment progress in Azure Portal
Step 7: Access outputs from terraform output command
Step 8: Test connectivity between VMs and subnets
Step 9: Use terraform destroy to cleanup resources when finished

🎯 Advanced Features & Patterns

Terraform Meta-Arguments & Patterns

  • count: Used for deploying multiple identical VMs (3 Windows instances)
  • for_each: Available for map-based iteration (see commented examples)
  • depends_on: Manages resource dependencies (e.g., marketplace agreements)
  • locals: Defines local values for naming and tagging consistency
  • Data interpolation: Uses Terraform functions for dynamic resource naming

Network Design Patterns

  • Hub-and-Spoke VNet Peering: Demonstrates multi-VNet connectivity
  • Tiered Subnets: App, Web, Database separation for security
  • Security Group Rules: Allow all traffic template (customize for production)
  • Route Tables: Custom routing with specific route prefixes
  • Bastion Host Ready: Infrastructure prepared for secure remote access

Best Practices Implemented

  • ✅ Modular configuration with separate .tf files for concerns
  • ✅ Variable-driven customization with terraform.tfvars
  • ✅ Consistent naming conventions via locals
  • ✅ Resource tagging for organization and cost tracking
  • ✅ Output definitions for important resource references
  • ✅ State backend configuration for team collaboration

📝 Customization Guide

This project is designed for training and can be easily customized:

VM Count Modify count = 3 to deploy different number of Windows VMs
Address Spaces Update terraform.tfvars with your desired CIDR blocks
VM Size Change Standard_DS1_v2 to other Azure VM SKUs
Security Rules Replace "Allow_All" rules with specific port/protocol requirements
Enable Load Balancer Uncomment Loadbalancer.tf resources for high availability setup
Add Bastion Host Uncomment Bastion resources for secure remote access
